Rackcheck found an issue for the property "PolTree-migration-remove-correctness" where the migration created by a PolTree was not the same as the naive migration. 

The problem was in the 'migrate-arr-del' metafunction, which is responsible for correctly projecting an array. This metafunction is essentially a for loop that traverses an array from left to right and projects all sub-values. 

The metafunction was the following (problem line highlighted): 

	(define-metafunction PolTreeLang
	  migrate-arr-del : arr arr tree env ps p natural -> (δ ...)

	  [(migrate-arr-del (A v_fh v_ft ...) (A v_sh v_st ...) tree env ps (k ...) natural)
	   (δ_1 ... δ_2 ...)
	   (where natural_inc ,(add1 (term natural)))
------->>> (where (δ_1 ...) (migrate-del v_fh v_sh tree env ps (k ... (I natural))))
	   (where (δ_2 ...) (migrate-arr-del (A v_ft ...) (A v_st ...) tree env ps (k ...) natural_inc))]

	  [(migrate-arr-del (A v ...) (A) tree env ps p natural)
	   ()])

The problem is that, when descending into objects, the argument "ps" which is supposed to indicate which paths of the object should be traversed, it is not destructed. For arrays this path selector would be of the form (A* <rest>), and it was passed as-is to project sub-objects.

The solution was the following (modified lines highlighted). 

	(define-metafunction PolTreeLang
	  migrate-arr-del : arr arr tree env ps p natural -> (δ ...)

---->>>	  [(migrate-arr-del (A v_fh v_ft ...) (A v_sh v_st ...) tree env (A* p-exp_2 ...) (k ...) natural)
	   (δ_1 ... δ_2 ...)
	   (where natural_inc ,(add1 (term natural)))
---->>>	   (where (δ_1 ...) (migrate-del v_fh v_sh tree env (p-exp_2 ...) (k ... (I natural))))
---->>>	   (where (δ_2 ...) (migrate-arr-del (A v_ft ...) (A v_st ...) tree env (A* p-exp_2 ...) (k ...) natural_inc))]

	  [(migrate-arr-del (A v ...) (A) tree env ps p natural)
	   ()])
