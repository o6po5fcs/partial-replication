Rackcheck found a discrepancy in output between the naive migration and the poltree migration.

The problem is that the migrate-del-arr metafunction was including too many delete-operations in its output, even for paths that are still accessible. For example, a test based on a path from the output below: 

> (term (is-PolTree-readable (((ALLOW (𮕐񝠘 A* A*)))
  ((𮕐񝠘 (((ALLOW (𮕐񝠘 A* A*))) ((A* (((ALLOW (𮕐񝠘 A* A*))) ((A* (() ())))))))))) (𮕐񝠘 (I 0)) (O)))
#t

If the path should really be deleted, then is-PolTree-readable should return #false instead of #true. Hence the inclusion of `(!! (𮕐񝠘 (I 0))` in the output is wrong.

The cause is that migrate-del-arr did not stop traversal at the end of the provided path selector, so it would traverse too deep into an array that was unaffected by the removed privilege (thus: it could not possibly have its readability changed).
